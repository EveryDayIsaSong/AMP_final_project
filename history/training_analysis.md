## 训练曲线分析（共10张图）

### 1. `disc_demo_score` — 判别器对演示数据的打分 ≈ 0.86
**趋势**：初期快速升至 ~0.88，短暂跌到 ~0.77 后恢复，之后稳步上升到 0.86-0.87 并稳定。

**分析**：判别器对真实演示数据的打分稳定在 0.86。在 LSGAN 中，判别器训练目标是给 demo 数据输出 +1。当前 0.86 说明判别器能较好地识别演示数据。但关键要看和 disc_score 的差距。

### 2. `Loss/amp/disc_score` — 判别器对策略数据的打分 ≈ -0.865
**趋势**：初期从 -0.78 下降到 -0.87，之后在 -0.86~-0.87 范围内稳定。

**分析**：判别器对策略数据的输出约 -0.865，接近 LSGAN 目标值 -1。这说明判别器几乎完全能区分策略输出和真实数据。

**关键指标：gap = disc_demo_score - disc_score ≈ 0.86 - (-0.865) = 1.73**。理想状态下 gap 应 < 0.5（判别器难以区分），当前差距非常大。

### 3. `Episode_Reward/style` — 风格奖励 ≈ 0.7
**趋势**：0→500 步快速从 0.1 升到 0.8（峰值），500→1000 步**下降**到 0.6，之后稳定在 0.7。

**分析**：⚠️ style reward 在 ~500 步时达到峰值后开始下降。这直接对应了用户观察到的现象：1000步时步态自然，往后步态退化。

### 4. `track_ang_vel_z_exp` + `track_lin_vel_xy_exp` — 速度跟踪奖励 ≈ 0.28
**趋势**：两个曲线都持续缓慢上升，从 0 升到 ~0.28-0.29。

**分析**：速度跟踪奖励只有 0.28（最大值 1.0），说明策略对速度指令的跟踪能力较差。策略可能学会了以某个固定速度行走，恰好和随机指令有部分重叠。

### 5. `dof_acc_l2` — 关节加速度惩罚 ≈ -0.009
**趋势**：从 ~-0.002 急剧下降到 ~-0.008，之后持续缓慢变负。

**分析**：关节加速度持续增加，但量级变化不大。

### 6. `train/mean_reward` — 总奖励 ≈ 6.5
**趋势**：持续上升，从 0 升到 6.5。

**分析**：总奖励在涨，但 style reward 在降。说明 task reward 在涨，代价是牺牲了步态风格。

### 7. `mean_episode_length` — 平均回合长度 ≈ 850
**趋势**：快速升到 ~850 后稳定。

**分析**：机器人能稳定行走不倒。但稳定行走 ≠ 跟随指令。

### 8. `AMP/mean_style_reward` ≈ 14 + `AMP/mean_total_reward` ≈ 12
**趋势**：两者都是 0→500 步快速上升，然后 style 从 16 降到 ~14，total 从 12 降到 ~10 再回到 12。

**分析**：style reward 在后期有下降趋势，total reward 基本持平——策略在用"走形"的步态换取 task reward。

## 奖励量级分析

### 完整计算链

```python
# ppo_amp.py:131-133
style_rewards, disc_score = amp_discriminator.predict_style_reward(disc_obs, dt=step_dt)
rewards_lerp = lerp_reward(task_reward=rewards, style_reward=style_rewards)

# amp.py:201-203
lerp_reward = 0.3 * task_reward + 0.7 * style_reward
```

### Style reward 计算

```python
# amp.py:186,192
rew = clamp(1 - 0.25 * (disc_score - 1)^2, min=0)
style_reward = dt * style_reward_scale * rew
             = 0.02 * 5.0 * rew
             = 0.1 * rew
```

当 disc_score ≈ -0.865：
```
rew = 1 - 0.25 * (-0.865 - 1)^2 = 1 - 0.87 = 0.13
style_reward = 0.02 * 5.0 * 0.13 = 0.013/步
```

### Task reward 估算 ≈ 0.54/步

### 最终 Lerped reward

```
lerp = 0.3 * 0.54 + 0.7 * 0.013 = 0.162 + 0.009 = 0.171/步
```

**虽然 style 在 lerp 中占 70% 权重，但由于 style_reward 绝对值太小（0.013 vs task 0.54），task 实际贡献了 95% 的训练信号。**

## 问题1分析：不听使唤

task reward 确实主导了训练信号（95%），但速度跟踪奖励只有 0.28/1.0。机器人不是"完全忽略指令"，而是学会了以某个固定速度行走，这个固定速度恰好和随机指令有部分重叠，平均下来能拿到 0.28 的跟踪奖励。

**为什么不真正跟踪指令？** 策略发现了一个"偷懒"策略：以数据中的行走速度固定走，既可以从 AMP discriminator 拿到一些 style reward（因为步态部分像数据），又可以在随机指令上"蒙"到一些跟踪奖励。真正去跟踪每个不同指令需要大幅改变运动模式，这会让 style reward 进一步下降，总奖励反而可能更低。

## 问题2分析：步态退化（身体前倾 + 脚后跟抬太高）

style_reward 始终是 ~0.013/步（接近零的常数），在 PPO 中 advantage = R + γV(s') - V(s) 趋近于零，**style reward 完全不提供梯度信号**，AMP discriminator 形同虚设。

而 task reward 中：
- `flat_orientation_l2`（权重 -1.0）惩罚身体倾斜，但身体前倾带来的速度跟踪收益可能超过倾斜惩罚
- `feet_air_time_positive_biped`（权重 +0.5）鼓励摆动脚在空中停留（≤0.4s），没有上限约束
- **没有任何惩罚项限制脚的绝对高度**

策略发现：身体前倾 + 抬高脚 = 更快的行进速度 = 更好的速度跟踪奖励。而 style reward 太弱无法阻止。

## 两个问题的共同根因

**`disc_learning_rate = 1e-4` 太高了。**

默认值（`amp_cfg.py`）是 `1e-5`，G1 配置改成了 `1e-4`（10 倍），和策略学习率一样。

Discriminator 的任务（二分类）比策略的任务（高维连续控制）简单得多。相同学习率下，discriminator 进步远快于策略，导致：
1. style_reward 很快跌到接近零 → 失去约束步态的能力 → 问题2
2. 策略转而只优化 task reward，发现"固定速度走"比"真正跟踪指令"更容易 → 问题1

---

## 调参方案

### 核心修改

| 参数 | 当前值 | 修改为 | 依据 |
|---|---|---|---|
| `disc_learning_rate` | 1e-4 | **1e-5**（恢复默认值） | discriminator 进步太快，style reward 被压到接近零，AMP 失去作用 |

### 如果效果不够，备选方案

| 参数 | 当前值 | 备选调整 | 依据 |
|---|---|---|---|
| `task_style_lerp` | 0.3 | 0.5 | style reward 上来后，提高 task 权重来强化指令跟踪 |
| `style_reward_scale` | 5.0 | 3.0 | 如果 style 过强导致忽略指令，可降低 |

## 结论

降低 disc_lr 到 1e-5 的效果：
- ✅ 大幅提升了 style reward（0.70→0.96），步态更自然
- ✅ 延长了自然步态窗口（从 ~500 步到 ~600+ 步）
- ❌ **没有解决指令跟踪**——速度跟踪奖励几乎不变（0.28→0.32）
- ❌ **没有阻止最终退化**——只是推迟了（从 ~1000 步推迟到 ~2200 步）

退化仍然发生的根因：discriminator 只是被放慢了，随着训练进行最终还是变强了，style reward 从峰值 1.5 跌到 0.96。

指令跟踪不改善的根因：与 disc_lr 无关。style_reward 经过 `dt × scale` 缩放后只有 ~0.096/步，而 task_reward 是 ~0.54/步。不管 disc_lr 怎么调，style 在 lerp 中的实际占比太小（~9-29%），策略没有足够的动力在保持 style 的同时去跟踪指令。

## 下一步方案分析

### 方案1：继续调参从头训练

需要解决的问题：
1. 步态退化 → 需要进一步降低/冻结 disc_lr
2. 指令不响应 → 需要让 style_reward 量级与 task_reward 可比

但存在矛盾：
- 要步态稳定需要 style 足够强
- 要指令响应需要 task 足够强
- 当前 style_reward（~0.096/步）vs task_reward（~0.54/步），差距太大
- 即便 `task_style_lerp=0.5`，实际比例也是 85% task vs 15% style
- 从头训练无法保证复现 600 步时的自然步态质量

### 方案2：从 600 步权重 fine-tune（✅ 当前采用）

600 步时 style reward 高达 ~1.5（峰值），步态非常自然。策略已经学会了"像数据一样走路"，缺的只是"听指令"。

Fine-tune 思路：
1. **冻结 discriminator**（`disc_learning_rate=0`），保持 style reward 稳定不退化
2. **提高 `style_reward_scale`**（5→20），让 style_reward 量级（~0.48/步）与 task_reward（~0.54/步）匹配
3. **提高 `task_style_lerp`**（0.3→0.5），给 task 更多权重推动指令跟踪

为什么冻结 discriminator 是关键：
- 步态退化是因为 discriminator 越来越强，style reward 被压低
- 冻结后 style reward 保持恒定（~1.5 的高水平），策略始终有强烈的"像数据"的信号
- 策略只需在一个稳定的 style landscape 上学习跟踪指令
- 这是 AMP/deep mimic 领域的标准做法：先学 style 再固定 style 学 task

具体修改：

| 参数 | 修改前 | 修改后 | 依据 |
|---|---|---|---|
| `disc_learning_rate` | 1e-5 | **0**（冻结） | 保持 style reward 稳定，防止退化 |
| `task_style_lerp` | 0.3 | **0.5** | 提高 task 权重，推动指令跟踪 |
| `style_reward_scale` | 5.0 | **20.0** | 让 style_reward（~0.48/步）与 task（~0.54/步）量级匹配 |
